# Architecture (milestone 2)

Workspace crates:

| crate | role |
|---|---|
| `onyx-buffer` | `Buffer`: ropey rope, sorted `Range` selections, `Edit` batches applied in reverse offset order, linear undo/redo (caps `MAX_UNDO`=1000 txns and `MAX_UNDO_BYTES`=64 MiB, typing/backspace coalescing), atomic save, grapheme and display-column math. No terminal knowledge. |
| `onyx-term` | `Term` raw-mode guard (restores on drop and from a panic hook, since release uses `panic=abort`), `Screen` cell grid with diffed flush into one `write_all` per frame. |
| `onyx` | CLI, event loop (block on input, drain queue, render once), rendering incl. the command palette overlay. `commands.rs`: `Cmd`, the `REGISTRY` of named commands with default keys, `map_key`, palette `filter`. |

Key bindings: `Keymap` (commands.rs) starts from `REGISTRY` defaults and applies `~/.config/onyx/keys.conf` (or `--config <file>`): `key = command` lines, `key = none` unbinds, a command named in the file loses its defaults; bad lines are skipped and reported in a toast.

Conventions: offsets are char indices; edits go through `Buffer::edit`, which records one undo transaction;
selections are always normalized (sorted, merged). Every action is a `Cmd`; keys resolve through `REGISTRY` (name, canonical key spec, constructor).

Dependencies: `ropey` (rope), `crossterm` (events/escapes; default features off), `unicode-width`,
`unicode-segmentation`; dev: `proptest`.

Buffers: `App` holds the active doc in its own fields and parks the rest in `docs` (slot `cur` is a placeholder); `switch` swaps them. Files come from the CLI or the Ctrl+O tree overlay (`filetree.rs`) or the `open-path` prompt (status-line input, no completion; reopening an open file switches to it).

Known limitations: wrap (on by default, Settings "Word wrap") is display-only: Up/Down/Home/End still move by logical line; no syntax,
non-UTF-8 files are treated as Latin-1 (lossless round-trip; saved as UTF-8 once a char above U+00FF is added), not detected as other encodings, ARM build unverified on this machine (no armv7 std target installed).

Plugins (milestone 3, design and protocol in `PLUGINS.md`): `plugin.rs` spawns each `~/.config/onyx/plugins/<name>/` executable and speaks a tab-separated line protocol over its stdin/stdout (reader thread per plugin into an mpsc queue, bounded writer queue). Plugins register commands, draw panes (`pane.rs`: docked right/bottom layout, focus routes keys to the plugin) and edit the active buffer through the same `Buffer::edit`. Example plugin: `examples/plugins/hello`. `crates/terminal` (`onyx-terminal`, deps `vt100` + `libc`) is the first real plugin: a shell on a pty in a bottom pane; it is a separate binary so the editor keeps its four dependencies.

Modes (`MODES.md`): `App.study` / `study_word` gate `study_key` (typing swallowed; marks wrap the selection or word; `[[bookmark]]` markers; Enter mark menu). Right-Shift word navigation (`rshift_key`) tracks `KeyCode::Modifier(RightShift)` events from the kitty protocol, enabled by `onyx_term::keyboard_enhancement`.

Speedreader (`SPEEDREADER.md`): `speedread.rs` (tokenize, ORP, timing, navigation; pure) and `reader.rs` (`Reader` state, keys, drawing); `App.read` swallows keys and draws over the editor rect, the event loop waits for `Reader::next_due`. Exit moves the caret to the last word shown.

Milestone 5: `markers.rs` (pure marker search over the buffer text), `menu.rs` (menu table, `Bar` cursor state, `AltTap` lone-Alt detector, `title_spans`), `wrap::width` (effective wrap column). New `Cmd`s: `WrapWidth`, `Marker`, `SelectLine`, `Indent`, `UnindentLines`, `MenuBar`; overlay state `wrap_menu` and `menubar` in `App` (the menu bar draws last, over everything).

Milestone 4 (`FEATURES.md`): `settings.rs` (data-driven settings and panel rows, layering), `editview.rs` (draws one view; used for every split), `chrome.rs` (tabs, sidebar), `minimap.rs`, `indent.rs`, `multi.rs`, `search.rs` (regex engine wrapper, project walker), `fuzzy.rs`, `goto.rs`, `symbols.rs`, `findbar.rs`, `snippets.rs`, `build.rs`, `splits.rs`, `meta.rs` (per-document non-text state). `app/nav.rs` and `app/tools.rs` hold the `App` glue (find, goto, results, jumps, snippets, macros, builds, views). The editor gained one dependency, `regex`. Plugin crates: `pluginkit` (std-only protocol helpers), `syntax` (syntect), `spell` (hunspell pipe), `lsp` (serde_json). `Style` colours are `u32`: palette index or `rgb()`.

Links (milestone 28, `FEATURES.md`): `links.rs` (pure: `parse_line` finds `[[..]]`/`{{..}}`, `resolve` maps a target to files, `shorten`, `slice_fragment` for `#Heading`/`#L..`), `linkindex.rs` (per-file outgoing links and the backlink inverse, built on a thread from the project file list, one file re-read on save) and `app/linkui.rs` (the `App` glue: highlight spans fed to `editview`, the `[[`/`{{` picker, hover preview, follow-link menus and split opening, the right-docked backlinks panel drawn by `chrome::draw_right_panel`). State lives in `App.links`.

Insert menu (milestone 29, `FEATURES.md`): `app/insertmenu.rs` (`Ctrl+K` overlay list, heading sub-list, footnote/URL/date inserts, the `LinkNew` prompt) reusing the stage A picker (`linkui::Pop`) for Link and Transclusion; `links::headings` and `links::next_footnote` are the pure parts. `Settings.menu_icons` (`MenuIcons`) picks the icon column.

Transclusion (milestone 30, `FEATURES.md`): `embed.rs` (pure: `expand` turns fetched source text into display `Row`s with source offsets, nesting, depth and cycle limits, `caret_row`), `editview` virtual rows (`Opts.embeds`: a host line followed by N extra rows, counted in scrolling by `height` and in `pos_at`; there is no shared row table, folds still just skip lines) and `app/embedui.rs` (`embed_blocks` per frame for the visible window, a disk cache for sources that are not tabs, Space collapse, edit focus). Edit focus makes the source a real tab and runs each key with that doc's fields swapped into `App.buf/meta/top/left/goal` (`embed_swap`), so undo, selection and save are the source's own.

Folders: `App.folders` (empty by default; `root` stays the primary root), `app/folders.rs` (add/remove, resets the file list), `project_roots`/`rel` in `app/nav.rs` (union walk `search::walk_all`, `resolve_where` takes the roots), `sidetree.rs` (pure FOLDERS tree rows, expand state) and `app/sidebar.rs` (selection, keys, clicks, context menu) drawn by `chrome::draw_sidebar` with `TreeView`. Context menu and quick settings: `app/ctxmenu.rs`, `app/quickui.rs`, `openables.rs` (URL/path tokens).

Layouts: `layouts.rs` (pure: `Arr`, `Layout` parse/print, `build` trees per arrangement, `detect`), `splits::Node::Split` carries a `ratio`, `Settings.layouts` / `layout` (`layout.<name>` lines), `app/layoutui.rs` (picker, apply, reflow, save/rename/delete, `split_add` / `split_remove` with tab moving).

Data tree (milestone 32, `FEATURES.md`): `datatree.rs` (pure: `parse` = `views::check` then a span-recording scanner per format into `Row`s, `visible` for folds, `guide` for connectors, `normalize` for what an edit may write) and `app/treeui.rs` (state in `App.ex.tree`, `data_key`, `draw_data`; shares `CellEdit` with `tableui.rs`). `Settings.table_auto` / `tree_auto` gate `Sub::auto` in `apply_file_mode`.

Milestone 36: pure modules `when.rs` (friendly dates), `wordfreq.rs`, `timers.rs` (injected clock), `align.rs` (per-row offsets used by `editview::draw` and `pos_at`), `banner.rs`, `daylog.rs`; glue in `app/pipe.rs` (pipe and banner insert), `app/timersui.rs` (timers, focus events, writing log), the right sidebar tabs in `app/linkui.rs`, `lists::Kind::Entries` for data files. `onyx-term` enables focus reporting and `Screen::restyle` (ruler guides). New plugins `examples/plugins/dictionary` and `examples/plugins/rhyme` (bash).

Pictures (milestones 25, 38): `onyx-term::image` (decode: `png` + `zune-jpeg`, ImageMagick for other formats; resize, crop, blocks, kitty RGB, sixel encoder), `app/picture.rs` (viewer with zoom and pan), `app/inlinepic.rs` (threaded decode cache, `Pic` rows plus an optional `embed::Gfx` in the embed block map; `editview::draw` pushes it to `Screen.graphics`, which sends kitty data once per id and drops any graphic whose text-art `cover` cells were drawn over).

Milestone 37 (gutter marks, `FEATURES.md`): pure modules `bookmarks.rs` (`Bookmarks`: toggle, next/prev, `resync` by line text, `restore`, serialize; stored via `swap::path_for`-style names under `<config>/bookmarks`), `gitdiff.rs` (`diff_lines`: prefix/suffix trim plus LCS, one hunk above 4M line pairs) and `gutter_marks.rs` (`line_marks` merges bookmarks and git ranges into `LineMark { left, right }`; `cols` decides if the 2-cell column shows; `draw_cells`). `margins::GitMarks::poll(path, version, text)` runs `git show HEAD:./file` and the diff on a thread, throttled to 300 ms, returning true while a result is pending (the main loop then ticks at 150 ms). `app/bookmarkui.rs` is the `App` glue: `bm_cmd`, and `bm_frame` once per frame (lazy load, resync only when a bookmarked line no longer matches, debounced save, rebuild `App.gutter`). `editview::draw` takes the map in `Opts.marks` and `gutter_width(buf, line_numbers, mark_cols)`; views other than the active one use `editview::NO_MARKS`.
Bookmark list: `lists::Kind::Bookmarks` and `lists::bookmarks` (pure, items at line starts with a `●`/`○` label); `App::open_lists_at(start)` and the `Bookmarks` branch of `lists_load` build the items from `meta.bookmarks`; command `list-bookmarks` (`Cmd::ListBookmarks`).

Milestone 39 (study cards, `FEATURES.md`): `cards.rs` is pure: cloze `parse`/`hide`/`unhide`/`block_range` over char offsets, `cards_in` (one `Card` per cloze number: id = FNV-1a over path, number and hidden texts; context = the paragraph, split into `(text, hidden)` segments), `wrap_segs`, SM-2 `grade`, the schedule and `today` file formats with `prune`, `build_deck` and the `Session` queue (Again re-queues three places down). `app/cardsui.rs` is the `App` glue: `cards_cmd` (Ctrl+K, palette, context menu), `cards_collect` (reads project notes, or the open buffer, and the `<config>/cards/*.cards` rows), `cards_save` (schedule, `today`, `review.log` after every answer), and the review overlay (`CardsUi` in `Extras.cards`, key/mouse/draw hooks next to the layouts panel). `links::parse_line` skips `{{...::...}}` so a cloze is never an embed.

Milestone 43 (study sessions, `FEATURES.md`): `Timers` counts Work-phase milliseconds (`work_ms`, `take_work_ms`; away time and breaks excluded). `app/timersui.rs` keeps a session as `Extras.session` (the subject note, absolute) and appends drained focus time to `<config>/cards/sessions.log` (`session_flush`: each minute, each phase end, on stop; `timers_tick` ends the session when the pomodoro stops). `studystats.rs` adds `parse_sessions`, `day_ms` (reviews capped at 60 s plus session time per day), `heat_grid` (Monday-first, rank-quartile levels) and `add_sessions`; `study_stats` draws them. `l` in review calls `App::open_related` (backlinks from `links.ix`, started by `cards_review`) into the `StudyUi` list.

Milestone 42 (Anki and home review, `FEATURES.md`): `ankiio.rs` maps Anki fields to `{{cN::text}}` paragraphs (HTML reduction, hint stripping, basic notes as `front {{c1::back}}`), reads and writes Anki plain text (TSV), and reads and writes legacy `.apkg` by running `unzip`, `zip` and `sqlite3` in a scratch folder (`read_apkg` uses `json_each` and `hex` so no JSON parser is needed). `app/ankiui.rs` has the three prompts (export TSV, export `.apkg`, import) with a press-Enter-twice confirm kept in `Extras.anki_confirm`. The home line is `App::cards_due_home` (cached in `Extras.due`, keyed by day and the sizes of `cards/index`, `review.log` and `exam` plus the daily new limit; reads indexed notes only) drawn by `welcome::draw` in the blank row under the menu.

Milestone 40 (quiz mode, `FEATURES.md`): `quiz.rs` is pure: `questions` (cloze cards from `cards_in`, heading bodies, list items under a heading; fenced code and cloze regions skipped), `selected_lines`, a seeded xorshift `shuffle`, and the `Session` (first-attempt score, one retry per miss). `app/quizui.rs` collects notes read-only (it never calls `cards_collect`, which prunes and registers on disk), handles keys and draws the result; `draw_card_panel` in `app/cardsui.rs` is the panel shared with the review screen. `QuizUi` lives in `Extras.quiz`.
