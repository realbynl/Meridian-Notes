# Milestone 4: Sublime parity (features, keys, files)

Everything the 🟢/🟡 list asked for, except the items under "Not done". Keys are defaults; every
command is in the palette (Ctrl+Shift+P, or F1 in terminals without the kitty protocol) and rebindable in `keys.conf`. Keys marked † need the kitty
keyboard protocol (or have an Alt alternative); `ctrl+h` arrives as Backspace in legacy terminals, so use `alt+h` there.

## Window and chrome
| feature | how |
|---|---|
| Fullscreen | `F11` / `Alt+F11` (command `fullscreen`; `Ctrl+T` is now New Tab). Asks the emulator to go fullscreen (xterm `CSI 10;1 t`, ignored by emulators without it) and hides the tab bar, sidebar, minimap and status bar; messages and prompts still show on the last row. Restored on exit. `onyx --fullscreen` / `-F` starts that way |
| Hide interface | `Alt+.` (`toggle-interface`, setting `hide_interface`, Settings row "Hide interface"; saved like any setting): hides tab bar, sidebar and status bar like fullscreen but keeps the minimap and line numbers, without asking the emulator for fullscreen |
| Touch | a touchscreen arrives as mouse events: tap places the caret, double tap selects a word, triple tap a paragraph, a fourth the whole document; tap a row in the palette, Goto or file tree to pick it, tap outside to close, swipe/wheel moves the selection |
| File tree | `Ctrl+O` (command `open-file`): overlay tree of the open file's folder. Up/Down move, Right/Left unfold/fold (Left on a top-level row, or Backspace, goes up a folder), `Enter` opens (or unfolds a folder), `Shift+Enter` opens the file and goes fullscreen, `Alt+H` shows hidden files, typing filters the tree to every entry under the root whose relative path contains the text (Backspace erases, Esc clears the filter, revealing the selected entry, then closes; Enter on a folder leaves the filter and unfolds it). `open-path` is the old type-a-path prompt |
| Tabs | text tab bar (`tab_bar = always|auto|off`), click to switch, middle-click closes |
| Open Files sidebar | `sidebar = on` / `toggle-sidebar` (`Ctrl+;`†); click a name to switch. While the interface is hidden (`Alt+.`), `Ctrl+;` shows or hides the sidebar on demand |
| Minimap | `minimap = on` / `toggle-minimap`; Braille cells, viewport shaded, click or drag to scroll. Single view only |
| Switch tab | `Ctrl+1`..`Ctrl+9` pick the n-th tab (`Ctrl+4` needs the kitty protocol: legacy terminals send it as `Ctrl+\`) |
| Splits | `Alt+2` columns, `Alt+8` rows, `Alt+O` next view, `Alt+0` close view, `Alt+1` only this view; click a view to focus. Two views of one file share the caret |

|---|---|

| Multiple cursors | `Ctrl+D` selects the word under every empty caret, then adds the next occurrence of the selection (wrapping), `Alt+F3` all occurrences, `Alt+D` every whole-word occurrence of the selection (or of the word under the caret), `Ctrl+Alt+Up/Down` add caret, `Alt+L` (palette `split-into-lines`) splits the selection into lines, `Esc` collapse, Ctrl/Alt+click adds a caret |

| Macros | `Alt+X` record/stop, `Alt+Shift+X` play (`macro-play`; `Alt+P` now adds the current file's folder to the project), palette `macro-save` names the last one (`~/.config/onyx/macros/<name>.macro`, listed as `macro.<name>`). Recorded as keystrokes, so it replays prompts and the find bar too |
| Wheel moves cursor | `wheel_moves_cursor = on` (Settings: Wheel moves cursor, default off): in the editor the mouse wheel moves the caret 3 lines up/down (view follows) instead of scrolling the view. Overlays, sidebars and terminal panes are unchanged. |
| Word / scroll keys | `Ctrl+Left/Right` move by word like Sublime: stops at word ends and at punctuation runs, `_` is a word char (`Shift` selects, so `Ctrl+Shift+Left/Right` extends). `Ctrl+Up/Down` page up/down; `ctrl_updown = scroll` (settings panel: Ctrl+Up/Down) makes them scroll one line without moving the caret instead (commands `scroll-up`/`scroll-down` are unbound but in the palette) |
| Surround selection | typing `'` `"` `` ` `` `(` `[` `{` `「` `『` `（` `【` `《` `〈` `“` `‘` over a selection wraps it (every selection) and keeps the inner text selected |

## Search and navigation
| feature | how |
|---|---|
| Find / Replace | `Ctrl+F` (Replace is the next panel: `Right` at the end of the Find text, `Left` on an empty field, or palette `replace`; `Ctrl+H`/`Alt+H` are History now); incremental, all matches highlighted, `n of m`; `Alt+C` case, `Alt+R` regex (groups `$1`/`\1` in the replacement), `Alt+W` whole word, `Enter`/`F3` next, `Shift+F3` previous, `Tab` Find↔Replace, `Alt+Enter` select all matches, `Alt+A` replace all |
| Find in Files | `Ctrl+Shift+F`† / `Alt+F`: Find, Where and Replace fields (`Tab` cycles, `Up`/`Down` move between them and `Up` from Find closes the panel; `Alt+C/R/W` options as in Find). Where takes comma-separated folders/files, `<project>`, `<open files>`, `<current file>`, wildcards (`*.rs` limits the search) and `-wildcards` (skipped), and defaults to the project root. `Enter` searches. `Alt+A` replaces in every file on disk: the first press counts and asks, a second press with the same fields writes (no undo; files with unsaved changes in the editor are skipped, open unchanged ones reload, non-UTF-8 files are left alone). Results open in a read-only "Find Results" buffer: `Enter` on a line (or `F4` / `Shift+F4`) jumps to it |
| Goto Anything | `Ctrl+P`: fuzzy file names (open buffers first). Suffixes: `file@symbol`, `file#text`, `file:line[:col]`, `$symbol` (whole project). `Ctrl+G` is `:` (also expressions: `+4`, `-2`, `4+4`, `20-5`, `3*4`, `100/4`; a leading `+`/`-` counts from where the caret was), `Ctrl+R` is `@`, `Ctrl+Shift+R` is `$`. Moving through in-file results previews them; Esc restores the view. `Left`/`Right` swap between Goto Anything and the Command Palette (either way), and `Ctrl+P` reopens whichever you used last (kept in `~/.config/onyx/last-palette`); `Ctrl+Shift+P` always opens the Command Palette. Use this where the terminal cannot send `Ctrl+Shift+P` (no kitty protocol). Typing `@` or `snippet: ` replaces the old empty-entry `Right` shortcuts |
| Symbols, goto definition | line-based indexer for Rust, Python, JS/TS, Go, C-family, shell, Ruby, Lua, PHP, TOML/INI, Markdown headings. `F12` jumps (a list when there are several). With a language server, `lsp.definition` is the exact one |
| Jump history | `Alt+-` back, `Alt+=` forward (goto, results, definitions) |
| Projects | root = nearest ancestor with `.onyx/` or `.git`. `<root>/.onyx/settings.conf` overlays your settings; `.onyx/snippets`, `.onyx/builds.conf` |
| Build systems | `Ctrl+B` / `F7` runs the first (or last used) build; palette has `build: <name>`. `builds.conf` lines are `name = command` (project and user files); Cargo, make, npm and go builds are guessed. Output streams into a "Build Results" buffer; error locations (rustc, gcc/clang, go, tsc, Python) jump with Enter / `F4` |

## Plugins (separate binaries, `scripts/install-plugins.sh`)
Protocol v2 (see `PLUGINS.md`) lets plugins receive `view`/`saved` events and send `spans`, `theme`, `goto`, `pick` and `status`.

* `onyx-syntax`: syntect, so real `.sublime-syntax` (`~/.config/onyx/syntaxes/`) and `.tmTheme` (`~/.config/onyx/themes/`) files. `color_scheme = <name or path>` also sets the editor colours; without it only token colours are applied. Truecolor (the screen layer now takes `#rrggbb`).
* `onyx-spell`: `spellcheck = on`, words through `hunspell -a` (`spell_dictionary = en_US` or a path), undercurl (red text where the terminal has no undercurl). Prose files whole, code only in comments and double-quoted strings. `spell.add-word` writes `~/.config/onyx/dictionary.txt`.
* `onyx-lsp`: servers from `~/.config/onyx/lsp.conf` (`rs = rust-analyzer`; rust-analyzer, pylsp, clangd, gopls, typescript-language-server, bash-language-server are tried by default). Diagnostics (undercurl, `E1 W2` and the message under the caret in the status bar), `lsp.hover` `Alt+K`, `lsp.completion` `Alt+/`, `lsp.definition`, `lsp.references`, `lsp.format`, `lsp.symbols`, `lsp.restart`. Full-document sync.
* `ignored_packages = a,b` in `settings.conf` skips plugins by directory name.

## Settings files
Colours: `color.<key> = #rrggbb | 0-255 | default` for `bg`, `fg`, `select-bg`, `select-fg`, `line-bg`, `gutter-fg`, `gutter-bg`, `gutter-current-fg`, `tilde`, `find-bg`, `accent` (active tab, status bar, menus, welcome page). The settings panel has a `Color:` row for each (Enter types a value, Del resets). They override a plugin's `color_scheme`. The rest of the tab bar and sidebar colours are not configurable yet.

`settings.conf` is `key=value`, layered: built-in defaults, `~/.config/onyx/settings.conf`, then `<project>/.onyx/settings.conf` (the panel edits the user layer). Sublime's names (`tab_size`, `block_caret`, `auto_hide_tabs`, `show_open_files`, `typewriter_mode_scrolling`, `ignored_packages`, ...) are accepted. Not JSON: it matches `keys.conf` and needs no parser.

## Milestone 14: encodings, line endings, binary and huge files
* **Line endings.** CRLF, CR and LF are detected on open (the most common wins; ties prefer LF, then CRLF), the text is held as LF, and save writes the file's own ending back. Mixed files are unified to the dominant one with a notice. The status bar shows the encoding and ending (`UTF-8  CRLF`, `*` after the ending when the file was mixed). Palette `line-endings-lf` / `-crlf` / `-cr` convert (the buffer becomes modified; save applies it).
* **Encodings.** UTF-8, UTF-8 with BOM, UTF-16 LE/BE (BOM required) and the old Latin-1 fallback all round-trip. Palette `encoding-utf8` / `-utf8-bom` / `-utf16-le` / `-utf16-be` / `-latin1` change what save writes. Latin-1 text that gains a char above U+00FF saves as UTF-8.
* **Binary files.** A NUL byte in the first 8 KB (and no UTF-16 BOM) opens a read-only hex dump of the first 1 MB in a tab named `<file> [hex]`. It cannot be edited or saved.
* **Huge files.** From 1 MB a file opens in huge mode (`HUGE` in the status bar): no lint, minimap, syntax/spell highlighting, word count, or view events to plugins. From 100 MB the status row asks `(o)pen anyway, (h)ex view of the start, Esc cancels` (files named on the command line open without asking).
* The external-change diff and swap recovery compare against the bytes save would write, so CRLF and UTF-16 files do not show every line as changed.
* Not done: sizes are constants (`HUGE_BYTES`, `BIG_BYTES` in `app.rs`), not settings; no lazy loading, so a 100 MB file still goes fully into memory; UTF-16 without a BOM is treated as binary; other encodings (Shift-JIS, Windows-1252 as distinct from Latin-1) are not detected; no per-file encoding picker on open; the huge flag is lost when Find in Files replace reloads an open file.

## Vim mode

Off by default. Turn it on with the Settings row `Vim mode`, `vim_mode = on` in `settings.conf`, or the palette command `toggle-vim-mode`. Code: `crates/onyx/src/vim.rs` (a state machine over the buffer's primary selection) and `App::vim_key`. The status line shows `NORMAL`, `INSERT`, `VISUAL` or `V-LINE`. It starts in Normal mode and is skipped in Study mode and read-only files.

* Motions: `h j k l`, arrows, `w b e` (also `W B E`, treated the same), `0 ^ $`, `gg G` (with a count, a line number), `f t F T` with `; ,`, `{ }`, `Ctrl+D/U`.
* Operators `d c y > <` with motions, counts, doubled for lines (`dd`, `2yy`, `>>`), and text objects `iw aw i" a" i( a( i{ a{ i[ a[ i<` and their `b`/`B` forms. `cw` acts like `ce`.
* Also `x X s S D C Y r J ~ p P u Ctrl+R`, `i a I A o O`, `v V` (Visual: motions, operators, `o`, `iw`, `p`), `/` (find bar), `n N`, `:` (command palette).
* Yanks and deletes also go to the system clipboard. `p` uses the last yank or delete.
* Ctrl shortcuts (Ctrl+S, Ctrl+Z, ...) work in every vim mode.
* Not done: `.` repeat, named registers, marks, `*`/`#`, `%`, `:` ex commands (`:w`, `:q`), block Visual, multiple carets, block caret in Normal mode.

## Prose lint (milestone 10)

Hemingway-style highlights in Write mode (`Mode::Writing`; `.md` and `.txt` files open in Write mode and are linted). On by default; turn it off with the Settings row `Prose lint`, `lint = off` in `settings.conf`, the palette command `toggle-lint` or the menu. Code: `crates/onyx/src/lint.rs` (`lint` per paragraph, `Cache` per buffer version) drawn through the `spans` closure in `app.rs`.

* Yellow: hard sentence (14+ words, ARI grade 10-13). Red: very hard (14+ words, grade 14+). Blue: adverbs (`-ly`, minus an exception list). Green: passive voice (a form of "to be" plus a participle). Purple: wordy phrases and filler (`utilize`, `in order to`, `very`, ...).
* Legend: a row above the status bar names each colour and counts its findings in the whole document (`Very hard to read 2  Hard to read 3  Adverbs 5 ...`). Hide it with the Settings row `Lint legend`, `lint_legend = off`, or `toggle-lint-legend`; `Ctrl+'` (and fullscreen) hides it with the rest of the interface. It needs a window at least 8 rows tall.
* Markdown images (`![alt](path)`, `![alt](<path>)`) are skipped.
* Word lists are built in and not configurable. Colours are fixed dark tints, not theme keys.
* Not done: a grade readout, per-category toggles, light-theme tints.

## Milestone 13: data safety
* **Atomic save keeps symlinks.** Saving a symlinked file writes through the link (temp file beside the real target, then rename); the link stays a link and permissions are kept.
* **Swap files.** Every 10 s each dirty file buffer is copied to `~/.config/onyx/swap/<name>-<path hash>.swp` (only when changed, none above 32M chars). The swap is removed on save, close and quit. If one is left when the file is opened, the status row asks `(r)ecover, (d)iscard, Esc later`; recovering is an undoable edit.
* **External changes.** Every 2 s the open file's mtime and size are compared with what was last read or written. A clean buffer reloads silently ("reloaded: file changed on disk"); a dirty one asks `(r)eload, (k)eep mine, (d)iff`. Reload is one undo step; Diff opens a read-only unified diff (`diff -u`, disk vs buffer) and keeps your text.
* Not done: only the active buffer is polled for changes (a background tab is checked when it becomes active); no focus-event trigger (the 2 s poll covers it); a deleted file is not reported; the swap holds text only (no caret or undo history).

## Milestone 15: code folding
- `F9` folds or unfolds the block at the caret (the caret line's own block, else the enclosing one); `Shift+F9` folds every block, `Alt+F9` unfolds all. `fold` and `unfold` are in the palette. Also in the View menu.
- Two kinds: **marker folds** (a line containing `{{{` up to its matching `}}}`, nested) and **indent folds** (the lines under a header that are indented deeper). Markers win on a line that has one.
- A folded header shows a dim note: ` ⋯ 12 lines, 3 TODOs`. Line numbers keep the real numbers, so the gap shows.
- Up/Down, PageUp/Down, mouse clicks, wheel scroll and scrolling to the caret all skip hidden lines. Moving the caret into a fold (Goto, Find, undo) opens it.
- A fold is remembered as its header line only and re-derived from the text each frame, so edits can never leave a stale range; headers below an edit move with the line count. Per document, not saved across sessions.
- Not done: syntax-aware folds (brace blocks without indentation), folds in split views other than the active one (they draw unfolded), fold marks in the minimap, saving folds across sessions.

## Milestone 16: context in the margins
- **Sticky scroll** (`sticky_scroll`, on by default; palette `toggle-sticky-scroll`, View menu, Settings): up to 3 enclosing declaration lines (found with `symbols.rs`, nested by indentation) stay pinned over the top rows of the editor, with their real line numbers. Markdown pins its enclosing headings by level (`#` over `##` over `###`). Headers on consecutive lines (a heading directly followed by its sub-heading) are pinned together, so none is hidden under the overlay. Works for every extension with Goto symbol rules (Rust, Python, JS/TS, Go, shell, Lua, C family, ...). Not drawn when the file has no symbol rules (or is `.txt`, or has no extension), the editor is under 8 rows, the file is huge, or the caret would be hidden under them.
- **Minimap marks** (`minimap_marks`, on by default; palette `toggle-minimap-marks`, Settings): the minimap's separator column shows git changes against HEAD (green added, yellow changed, red deleted-here); its last column shows diagnostics (red ●, from the plugin `diag` layer), find hits (■) and a caret trail (· for the last 8 places the caret rested, 4+ lines apart). ## Milestone 28: Links
Notes link to each other with `[[target]]`; `{{target}}` is the embed form; it is highlighted, completed and followed here and rendered by Milestone 30. Design: `docs/superpowers/specs/2026-10-05-zettelkasten-links-design.md` (stage A). All of it (including follow-link, which shows a toast elsewhere) works in Writing mode only (`.md`, `.txt`, unknown extensions); the backlinks panel itself shows for any file (empty for non-notes); Coding-mode files such as `.rs` keep `[[` and `{{` as plain text. The exact text `[[bookmark]]` (Study mode) is never a link.

| target | meaning |
|---|---|
| `NAME.md` | bare name: any project file with that name (several matches = ambiguous) |
| `Dir/NAME.md` | relative to the current file's folder, else to the project root, else a path suffix match |
| `/abs/x.md`, `~/x.md` | absolute, `~` is `$HOME` |
| `a;b` | candidates in order; the first one that resolves to a file wins |
| `target#Heading` | jump to that Markdown heading (it ends at the next heading of equal or higher level) |
| `target#L10-20` | line range (used by the preview; follow jumps to the first line) |
| no extension | `.md` is also tried |

- Highlight: link tokens are accent coloured and underlined, ambiguous ones amber, broken ones dim red (not underlined). Colours are constants, not theme keys. Resolution results are cached and cleared on save and when a file is created.
- Picker: typing `[[` or `{{` opens a list under the caret of project files (the whole walker file list, any extension), ranked by the text typed after the brackets. Up/Down choose, Enter or Tab insert the shortest target that resolves (file name if unique, else the path from the project root) plus the closing `]]`/`}}` unless already there, Esc closes, Backspace past the brackets closes. With no match the list offers `Create "<typed>.md"`; the file is only created when the link is followed. The picker also closes on a document switch, a menu bar, prompt or overlay.
- Hover preview: with the caret in a link and idle 300 ms, a popup under the caret shows the target path (plus `#fragment`, plus `(+n more)` when ambiguous) and its first 12 lines (the section for `#Heading`, the range for `#L..`). Broken links show `<target>: not found`. Any edit or caret move restarts it; it is hidden while a menu or picker is open.
- Follow: `Alt+Enter` (`follow-link`, also Edit menu) on the link under the caret. One target: opens in a split beside the current view (reuses a split already showing it) and jumps to the heading; `link_split = off` opens a tab instead. Several candidates: inline menu `Open which?` (Up/Down, Enter, Esc). Broken: inline menu `Create <path>` (Enter makes the file beside the current file, with folders, and opens it).
- Backlinks: `Ctrl+'` / `Alt+'` (`toggle-backlinks`, View menu, palette) shows a right-hand panel `Backlinks (n)` and focuses it, pressing again hides it. One row per link, `file:line text`. Up/Down move, Enter opens the linking file at that line (in a split when `link_split` is on, a tab when off), Esc gives focus back to the editor, a mouse click outside the panel does too. Width 30 columns, at most a third of the screen; not drawn under 80 columns, in fullscreen or with the interface hidden. The heading says `indexing...` until the background index is ready.
- Index (`linkindex.rs`): built on a thread from the project file list over `.md`, `.markdown`, `.txt` files (fixed list); one file is re-read when it is saved. It sees saved text only.
- Settings (Settings panel, `config`): `link_highlight` (on), `link_complete` (on, the picker), `link_preview` (on), `link_split` (on; off = tab), `backlinks` (off; the panel).
- Not done: embeds are rendered by Milestone 30; unsaved text and external changes are not indexed until saved; no `[[target|label]]` aliases; no click-to-select on backlink rows; the hover preview reads its file (up to 64 KiB) on the UI thread (the index itself is built on a background thread); headings inside fenced code blocks count as headings; mouse hover does nothing, only the caret triggers the preview.

Tested: unit tests for parsing, resolve (every target form, ambiguity, stale file-list hits), shortening, fragments, index build, incremental update and backlink inverse; tmux with a throwaway `HOME`: highlight colours (ok/broken/ambiguous), `[[` picker (filter, Esc, insert `sub/b.md`), `{{` picker, hover preview, `Alt+Enter` single (split), ambiguous menu (Down, Enter opens the second), broken (Create, file made), backlinks panel (`Backlinks (2)`, Down, Enter jumps to the line, Esc returns focus, `Ctrl+Alt+B` hides, click outside unfocuses) and a `.rs` file showing none of it. Not exercised: real mouse (clicks were injected SGR sequences), kitty-protocol keys, very large projects, indexing of unsaved edits.

## Milestone 30: Transclusion
A `{{target}}` that is alone on its line shows the target under it: the whole file, a `#Heading` section or a `#L10-20` range (same target forms as links). Design: `docs/superpowers/specs/2026-10-05-zettelkasten-links-design.md` (stage C), plan `docs/superpowers/plans/2026-10-05-zettelkasten-links-stage-c.md`. Writing mode only. The line stays a single real line in the host file; the shown rows are virtual (no line numbers, `embed-bg` background, header `━ {{target}} ━ ━ ...`, wrapped at the text width).
- Collapse: `Space` with the caret strictly inside the token (not at its edges, so typing next to it is unchanged) toggles between full and a 5-row view (`⋯ n more rows`). Also the command `toggle-embed`. State is kept per document by target text.
- Edit in place: `Enter` with the caret inside the token (command `edit-embed`) edits the source where it is shown. The source opens as a normal tab if it was not open (the tab shows its dirty dot, quit asks about it). Keys, undo/redo, selection, copy/paste and `Ctrl+S` act on the source only (host and source save separately). `Esc`, `Ctrl+C` (when nothing is selected; with a selection it copies), a mouse click, or the embed disappearing leaves. Commands that switch document or open overlays are refused with a hint. The caret stays inside the embedded region (section or range). A `[ Close ]` row sits under the embed while editing; `Down` on the last row selects it, and `Up` on the first row selects a matching one that is hidden until then. `Enter` on it closes the source tab; the same arrow again (`Down` on the bottom one, `Up` on the top one) leaves like `Esc`; the opposite arrow returns to the text. An embed taller than the window scrolls its own rows under the host line while you edit, so the caret and the Close row stay on screen.
- `Alt+Enter` or `Shift+Enter` (`follow-link`, `follow-embed`) opens the source in a split at the region (stage A follow). A split opened this way (also by following a `[[link]]`) shows a `[ Close ]` row on its last row. `Down` on the document's last line selects it; `Up` on the first line selects a matching one that is hidden until then. `Enter` or the same arrow again closes the split and its buffer (a dirty buffer asks again); the opposite arrow goes back to the text.
- Nested embeds expand read-only; deeper than 3 levels, or a file already on the path (including the host itself), shows `{{target}} (cycle)`. A missing file or section shows `not found` / `section not found`. Sources over 256 KiB show `too large to embed`.
- The hover preview is not shown for a rendered embed.
- Settings: `embed_render` (on; Settings panel "Show {{ }} embeds"), theme key `embed-bg`.
- Not done: only the active split expands embeds (others show the plain line); the minimap and sticky scroll ignore the extra rows; PageUp/PageDown count source lines, not rows; a click on embedded rows only puts the caret on the embed line (no click to edit); nested rows cannot be edited; embeds in the middle of a line are not expanded; Space/Enter just after startup act normally until the project file list has loaded.

Tested: unit tests for `embed.rs` (whole-line detection, section and range cuts with exact offsets, missing, empty, CRLF, no trailing newline, wrapping, collapsing, nesting, cycles, caret rows) and `editview` (virtual rows, scrolling, mouse mapping, edit caret); tmux with a throwaway `HOME`: render, `Space` collapse/expand and Space at the line start typing a space, `Enter` edit (tab opens, edit shows in the rows, source dirty and host clean, undo, `Ctrl+S` writes only the source, `Esc` back to the host, host undo leaves the source), `Ctrl+W` refused, a click ending focus, a `#Heading` embed (caret clamped to the section, deleting the heading shows `section not found`), a 24x12 window, `Alt+Enter` into a split. Not exercised: `Shift+Enter` (needs the kitty keyboard protocol), real mouse, word wrap off, very large projects, quitting with a dirty source.

## Milestone 31: Mode picker, table and data views
`Ctrl+M` / `Alt+M` (`mode-picker`) raises a panel from the bottom with the modes as columns: **Coding**, **Study**, **Writing**. Each column lists its views. Left/Right (or `c`/`s`/`w`) change column, the mode key again (`Ctrl+M` or `Alt+M`) closes the panel, Up/Down move, `1`-`5` pick a row at once, Enter picks, Esc closes, a click on a row picks it. `●` marks what is active. The old cycle is still there as the command `toggle-mode` (palette, Tools menu "Cycle Mode"), now without a key.

| column | rows |
|---|---|
| Coding | Code (plain source) · CSV / TSV table · JSON · YAML · TOML |
| Study | Caret · Word select · Speed reader |
| Writing | Prose |

Files start in their view by type: `.csv` `.tsv` `.tab` in the table, `.json` `.jsonc` `.geojson` `.ipynb` `.yaml` `.yml` `.toml` in the matching data view (`views::Sub::for_ext`). The view is per file (`Meta::sub`); the status bar says `CODING table`, `CODING JSON ok` or `CODING JSON line 3: expected ...`.

**Table view.** The buffer stays plain text; the grid is drawn over the editor (`table.rs` parses, `app/tableui.rs` draws). Columns line up (capped at 40 columns wide, the header row is bold and stays pinned), only the text of the selected cell is highlighted. Arrows, Tab/Shift+Tab, Home/End, PageUp/PageDown, Ctrl+Home/End and the mouse move; Enter edits the cell with the whole entry selected, then Left jumps to its start and Right to its end; typing on a cell replaces it; Enter commits, Tab commits and moves on, Esc cancels; Delete/Backspace clear a cell; Ctrl+C/X/V copy, cut and paste a cell. A commit is one replacement of that cell's char range (quoted when it holds the delimiter, a quote or a newline, CSV only; a tab or newline in a TSV cell becomes a space), so undo says `Undid: edit cell`. Ctrl+S, Ctrl+Z and the rest act on the buffer as usual. The delimiter comes from the extension, else the first line. Not done: adding or deleting rows and columns (switch to Code for that), column resizing, sorting, row-wise formulas, files over the huge-file limit (they stay text).

**JSON / YAML / TOML tree view.** These files open in a key/value tree drawn over the editor (`datatree.rs` parses, `app/treeui.rs` draws): one row per entry with `├─ └─ │` connectors, `▾`/`▸` on groups, values coloured by type. Up/Down/PageUp/PageDown/Home/End and the mouse move; Left collapses a group (or jumps to the parent), Right expands it; Enter on a group folds it. Enter on a value edits it with the whole text selected, typing replaces it, Enter commits, Tab commits and moves down, Esc cancels, Delete/Backspace clear it, Ctrl+C/X/V copy, cut and paste a value. A commit is one replacement of that value's char range (`Undid: edit value`); comments and formatting are untouched. A quoted string is edited inside its quotes (the caret and selection cover only the text between them; the quotes are put back, with `\"` escaped, on commit). On a `true`/`false` value, Up/Down while editing switch it. Text pasted into a string value is quoted for you (include a quote yourself to take it as written); other values must be a valid scalar, and an entry that would break the file is refused with a message. Multi-line values, YAML block scalars and groups are read-only here (edit them in Code view). If the file does not parse, the text view shows with the problem in the status bar (`CODING JSON line 3: ...`) and the tree returns once it is valid. The scanners behind it are small and hand-written (no parser dependency); `format-json` and `minify-json` still work. Files over 2 MB stay text. Not done: renaming keys, adding or deleting entries, YAML anchors.

**Auto-load settings.** Settings has "Table view for CSV/TSV" (`table_auto`) and "Tree view for JSON/YAML/TOML" (`tree_auto`), both on by default. Off, those files open as plain Code; the mode picker can still choose a view by hand.

Tested: unit tests for `table.rs`, `views.rs`, `datatree.rs` (spans, connectors, folding, quoting); tmux for the tree: JSON/TOML/YAML trees, fold, edit, undo, auto-quote, refused edit, invalid file falling back to text, both toggles; tmux with a throwaway `HOME`: the picker panel, a CSV opening in the table, move, edit (select-all, Left/Right, quoting of `Paris, FR`), save and `Undid: edit cell`, a JSON file (status, format, error line after a stray character). Not exercised: TSV, wide tables scrolling sideways in a real terminal, mouse clicks in the table, `Ctrl+M` itself (needs the kitty protocol; `Alt+M` was used).

## Milestone 32: Word swap (`Ctrl+K` / `Alt+K`)
On a month, weekday, number, ordinal, year, quarter, time or listed word, `Ctrl+K` or `Alt+K` opens a menu above and below it with the three neighbours each way (command `word-swap`, no key of its own). Up/Down walk it (the word itself is in between, nothing selected) and keep going past the three shown: the list scrolls for as long as the category has entries (numbers and years without end, a month or weekday list once round, ordinals up from 1st, scales to their ends). In a full date (`7th Dec 2026`, `Dec 31, 2025`) the caret on the month, day or year swaps the whole date and carries over: `Dec` has `7th Jan 2027` below it, and a day or month that does not exist in the new month or year is clamped (`31 Jan` → `28 Feb`). Enter or a click swaps, Esc keeps the word. On anything else the keys do what they did: `Ctrl+K` opens the insert menu, `Alt+K` is whatever it is bound to (the LSP hover plugin). Near the top of the screen the entries above would not fit, so the list is drawn under the word with a `(keep)` row where the word is. The last row names the category and what happens at its ends. Case and form are kept: `Aug`→`Jul`, `August`→`July`, `WED`→`TUE`, `wed`→`tue`, `Fifth`→`Fourth`, `9AM`→`8AM`, zero padding in `09`. The swap is one undo step (`Undid: swap word`).

| category | examples | at the ends |
|---|---|---|
| months, full and abbreviated | Aug → Jul, Jun, May / Sep, Oct, Nov | wraps (Dec → Jan) |
| weekdays, full and abbreviated | Wed → Tue, Mon, Sun / Thu, Fri, Sat | wraps |
| quarters | Q3 → Q2, Q1, Q4 / Q4, Q1, Q2 | wraps |
| times (`9am`, `9:30am`) | 9am → 8am, 7am, 6am / 10am, 11am, 12pm | wraps past midnight, am/pm follow |
| numbers, years, `FY26` | 5 → 4, 3, 2 / 6, 7, 8; 2026; FY26 → FY25... | extend without end (negative numbers too, `0` → `-1`) |
| ordinals and day numbers | alone: 12th → 11th, 10th, 9th / 13th, 14th, 15th; 1st → nothing above | extend upward, stop at 1st |
| a day next to a month (`Mar 1st`, `1st of March 2026`, `Dec 31, 2025`, `Mar 1`) | Mar 1st → Feb 28th, Feb 27th, Feb 26th / Mar 2nd, Mar 3rd, Mar 4th | the whole date is swapped; days roll over the month and the year (leap years too; a year is only changed if the date has one); month form, case and ordinal suffix are kept |
| word lists that wrap | morning/afternoon/evening/night, seasons, north/east/south/west, left/right/center, top/bottom/middle, and the pairs true/false, yes/no, on/off, enabled/disabled, and/or, public/private, up/down, open/closed, in/out, min/max, ... | wraps; a pair shows only the other word |
| ordered scales | x-small..x-large, low/medium/high/critical, todo / in progress / review / done, draft / review / approved / published, pending / active / complete, first..tenth, zero..twenty | stops at the ends |

Choices where the brief left room: a bare `1st` has nothing above, but next to a month it rolls back to the previous month's last day; `first` is the start of the ordinal words (so no `last`); `May` is read as the full month; `medium` and `review` belong to the first scale that lists them (sizes, todo-flow). Multi-word entries (`in progress`) are found as a phrase. The lists are in `wordswap.rs`.

Tested: unit tests for every example in the brief plus signs, dates, padding and phrases; tmux: the menu near the top (list mode) and lower on the screen, a swap and its undo toast.

## Milestone 33: Units, dates, colours
**Units** (`units.rs`, `app/unitui.rs`; setting `unit_hints`, on). With the caret on `5 miles`, `12 kg`, `5m`, `98.6F`, `8 km/h`: the unit is tinted, a popup above (below near the top) lists up to six conversions, readable ones first, and `Ctrl+K` or `Alt+K` replaces the text with the next one, in the style of the original (`5 miles` → `8.047 kilometres` → ..., `12kg` → `26.46lb`). Pressing it again moves on through the same list (worked out from the original number, so rounding never drifts) and comes back to the original. Dimensions: length, mass, volume, temperature, time, speed, data (decimal and binary). A one-letter unit must touch its number (`5m`, `10s`, `2h`), a spaced `in` is the word, `1st` is an ordinal. `5m` is ambiguous (metres, miles, minutes): the popup asks, `Ctrl+K` opens a short menu, and the answer is remembered for that spelling for the session. With no unit under the caret the key swaps a word, then picks a colour, else `Ctrl+K` opens the insert menu and `Alt+K` is its binding (hover). (Moved from `Ctrl+K`, which is the tree toggle plugin's again.)

**Dates on Tab** (`datephrase.rs`). Tab straight after `today`, `tomorrow`, `yesterday`, `next|last|this <weekday>` (`fri` too), `next|last|this week|month|year`, `+10 days`, `-2w`, `+3m`, `in 3 days`, `3 weeks ago`, `2 years from now`, `end of month`/`eom`, `end of year`/`eoy` replaces it with `YYYY-MM-DD` (today from `date`, so local time). `next friday` is the first Friday after today, `last friday` the one before, `this friday` today or later. A bare `friday` is left alone. Snippet triggers win over dates. One undo step (`Undid: expand date`).

**Colours** (`colors.rs`, `app/colorui.rs`; setting `color_swatches`, on). `#rrggbb` and `#rrggbbaa` are painted in their own colour (black or white text on top); `#rgb` and `#rgba` too in Coding mode only, since they collide with hashtags in prose. `Ctrl+K` / `Alt+K` with the caret on a code (after the unit and word-swap checks) opens an HSL picker over it (palette `color-picker`, no default key, also inserts `#808080` when there is no code): Up/Down choose H, S or L, Left/Right adjust (Shift for big steps), Enter writes it back in the same length and letter case, Esc cancels. Not done: no live preview in the text while adjusting (the popup has its own swatch), no RGB or alpha sliders, no `rgb()`/`hsl()` function colours.

## Milestone 34: Undo that explains itself, command ranking, key rebinding
- **Undo toast.** `Ctrl+Z` says `Undid: <step>` and `Ctrl+Y` `Redid: <step>`. Steps are named by what ran (`replace all [14 changes]`, `replace match`, `paste`, `cut`, `toggle comment`, `move lines up`, `indent`, `snippet`, `swap word`, `edit cell`, `expand date`, `convert unit`, `pick color`, natural palette phrases by their label) or described from the change (`typing [5 chars]`, `delete [1 char]`, `replace [3 chars for 5 chars]`, `edit [4 changes]`). `Buffer::label_last`, `undo_label`, `redo_label`. The toast lasts the usual second.
- **Palette order.** Within each match group (prefix, substring, subsequence) the commands you run most and most recently come first (counts halve every 14 days); with an empty box that is the whole list. Counted: palette picks and key presses; not counted: movement, deleting, typing, scrolling, tab switching. Stored in `~/.config/onyx/usage`. The key of each command was already shown at the right of its row.
- **Key rebinding.** Settings > Keys > `Key bindings` lists every command with its key (`*` marks a changed one). Type to filter, Enter then press the new key, Backspace instead unbinds it, Esc cancels; Delete in the list goes back to the built-in key. Edits rewrite `~/.config/onyx/keys.conf` in place (comments and other lines kept) and apply at once; a key that was another command's moves to the new one. Only keys that are bindings work (Ctrl or Alt chords, function keys, arrows...); a plain letter types text. `Esc` cannot be bound there, as it cancels. Terminals only deliver the combinations they report, as everywhere else.

Tested: unit tests for `usage.rs`, `keyconf.rs` (edits applied to a real `Keymap`), `datephrase.rs`, `units.rs`, `colors.rs`; tmux with a throwaway `HOME`: the unit popup, the ambiguity question and answer, a conversion cycle (`Ctrl+.` sent as the raw `CSI 46;5 u` bytes), Tab on `next tuesday`, the colour picker, rebinding `word-swap` to `alt+j` (keys.conf written). Not exercised: unbinding and reset in the UI (unit-tested only), a day-old `usage` file.

## Milestone 38: Inline pictures, native decoding, zoom and pan
- Inline: a line that is only `![alt](path)` / `![](<path with spaces>)` / one `<img src="...">` shows the picture under the line, up to 96x24 cells, aspect kept (`app/inlinepic.rs`). ## Radial menu (Ctrl+J / Alt+J)

`Ctrl+J` (`radial-menu`, also `Alt+J`) opens a small cross, entries in the accent colour (dark text on it; the selected one lighter), centred on the caret (nudged to stay on screen); everything else on screen is dimmed while it is open. Every level has four slots, the cardinal directions: north, east, south, west, filled in that order by the level's entries (at most four per level). The arrow keys pick the entry in their direction at once: Up north, Right east, Down south, Left west. `1`-`4`, `Tab` and `Enter` also work; `Esc`/`Backspace` go up a level (and close from the top), `Ctrl+J` again closes, `e` opens the editor. The mouse hovers, left-clicks to pick, right-clicks to go up, and clicking elsewhere closes. A category (`›`) opens its own cross around the entry you picked, which stays in the middle (darker, underlined), so the way you went reads the same on screen; the entries passed on the way stay drawn in darker shades of the accent (each older level darker still). The menu slides as needed to stay on screen. A line under the cross shows the path and what the selected entry does.

The menu is the `radial_menu` line of `settings.conf`: `Modes{Coding=mode-coding, Study=mode-study, Writing=mode-writing}, Save=save`. `Label=command` runs any command by its palette name; `Label{...}` is a category and nests. Entries past the fourth at any level are dropped when the file is read. The default is Modes, Save, Find and More (Palette, Settings, Layouts). `mode-coding`, `mode-study`, `mode-writing` set a mode directly (no default key).

Editor (Settings > Radial menu, the `radial-edit` command, or `e` in the menu): the tree as an indented list with each entry's direction (N/E/S/W). `a` adds after the selected entry, `n` adds inside the selected category, `Enter`/`e` edits, `d`/`Del` deletes, `Shift+Up/Down` reorders (which changes its direction), `R` resets to the default. An entry is typed as one line in the config's syntax (`Label=command`, or a bare `Label` for an empty category); unknown commands are refused, and a fifth entry in a level is refused. Every change is saved at once. Code: `radial.rs` (format, slots), `app/radialui.rs`, `app/radialedit.rs`.

## Milestone 45: Emmet, part a (HTML expansion) (2026-10-09)

Tab after an Emmet abbreviation expands it in `html htm xhtml php phtml twig erb ejs njk hbs vue svelte jsx tsx` files (JSX/TSX write `className`, `htmlFor` and `<br />`). Order on Tab: snippet trigger, Emmet, date phrase. One undo step (`Undid: expand emmet`). Setting `emmet` (Settings: "Emmet", default on).
- **Syntax:** `tag`, `#id`, `.class`, `[a=b c="d" e]`, `{text}`, `>` child, `+` sibling, `^` climb, `( )` group, `*N` repeat (1-500, and at most 2000 elements in all, so nested repeats cannot hang the editor), `$` numbering (`$$` padding, `$@-` down, `$@3` start; so a literal `$` cannot be typed in an abbreviation), implicit tags (`ul>.a` is a `li`, `table>.a>.b` is `tr` then `td`, `p>.a` is a `span`, otherwise `div`), default attributes (`a` href, `img` src/alt, `link`, `script` src, `input` type, `form` action, `label` for), void tags, `!` for the HTML5 skeleton. `{text}` and `[attr=value]` go before `*N` (`li{x}*3`).
- **Output:** a block element puts its children on their own lines; inline elements (`a`, `span`, `em`...) and elements whose children are all inline stay on one line (`div>span` is one line). Tab stops `$1`.. in document order: empty attribute values and empty element bodies; Tab walks them.
- **Safety:** a bare word with no operator (`foo`, `3`) expands only if it is a known HTML tag. A malformed abbreviation does nothing (Tab indents), and neither does a word right after `<` or `</` (a tag being typed by hand). Nothing happens inside a tag, comment, `<script>`/`<style>` body, `<?php ?>`, `<% %>`, `{{ }}` or `{% %}`, with several carets or a selection, in read-only buffers, or past 2 MB of text.
- Not done (later parts of Emmet): CSS abbreviations (45b), wrap with abbreviation (45c), balance-tag / select-next-item / update-tag (45d), `lorem`, filters (`|c`, `|bem`), custom abbreviations.

## Milestone 46: Emmet, part b (CSS abbreviations) (2026-10-09)

Tab after a CSS abbreviation expands it to a declaration: `m10` is `margin: 10px;`, `p10-20` is `padding: 10px 20px;`, `-m10` is `margin: -10px;`, `df` is `display: flex;`, `tac` is `text-align: center;`, `c#f` is `color: #fff;`, `m10!` adds `!important`, `bgcol` finds `background-color` by fuzzy match. Works in `css scss less sass styl` files and, in `html`-like files, inside `<style>` bodies and `style="..."` values. It only fires where a declaration can start (inside a block, after `{`, `;` or `}`; first on an indented line in Sass and Stylus), never in selectors, comments, strings or `url()`. Sass drops the `;`, Stylus drops the colon too. A word that is no alias and fits no property (`foo`) still indents, and so does a bare HTML tag name of three or more letters (`table`, `main`), which is a nested selector; template blocks (`<?php ?>`, `{{ }}`, `<% %>`) inside a `style=""` value do not block expansion; a full property name (`color`) expands to `color: ;`. Same `emmet` setting, same Tab order, one undo step.

- Units: bare numbers get `px`; `p` is `%`, `e` is `em`, `r` is `rem`; `z-index`, `opacity`, `line-height`, `font-weight`, `flex`, `order` stay unitless; `0` stays `0`. A doubled `-` makes the next value negative (`m10--5`). An unknown word in a value list is kept as typed.
- Not done: vendor prefixes, gradients (`lg()`), `@` at-rule abbreviations, custom abbreviations, `<style lang="sass">` bodies (read as CSS), indented lines under a Sass `//` comment still expand, fuzzy ties go to the more popular property (`bgra` is `background-image`).

Code: `emmet_css.rs` (pure: `expand`, `find`, `context_ok`, `html_context_ok`, `dialect`), `App::try_emmet` and `emmet_insert` in `app/extras.rs`. Spec `docs/superpowers/specs/2026-10-09-emmet-css-design.md`, plan `docs/superpowers/plans/2026-10-09-emmet-css.md`.

## Milestone 47: Emmet, part c (wrap with abbreviation) (2026-10-09)

`Alt+B` (`emmet-wrap`, also in the palette) opens a one-line prompt in `html htm xhtml php phtml twig erb ejs njk hbs vue svelte jsx tsx` files; the abbreviation typed there wraps the selection, or with no selection the current line without its indentation and trailing whitespace. `div.box` around `hello` gives `<div class="box">hello</div>`. The deepest, last element of the abbreviation holds the text. A bare `*` on that element (`ul>li*`) makes one copy per non-blank selected line (blank lines dropped, lines trimmed, `$` numbering works); with an ancestor multiplier the lines cycle. Multi-line text without `*` makes the element a block with the text on its own lines, one step deeper, common indentation removed. Text is escaped for the snippet engine (`$ } \` arrive literally). Empty attribute values keep their Tab stops, then the caret lands after the whole result. Esc cancels. One undo step (`Undid: wrap emmet`). Setting `emmet` off, a stylesheet, several carets, a read-only file, or nothing to wrap give a toast and no prompt.

- Rulings: a bad abbreviation (parse failure, `!`, a void tag as target, more than 500 lines with a bare `*`) keeps the prompt open and shows "Not an Emmet abbreviation" in the prompt label, not a toast (the prompt is drawn over the toast row); the label returns to normal when the text is edited. Unknown bare tag names (`my-widget`) are accepted. Leading and trailing whitespace of a selection (indent, line breaks) is left outside the replaced range, so a selection of whole indented lines keeps its indentation and the newline after it. A `{text}` on the target is replaced by the content.
- Known, older: Tab expansion's undo toast says `Undid: indent` rather than `Undid: expand emmet`, because the generic command wrapper in `app.rs` relabels every Tab after the fact (the undo itself is one step).
- Not done: live preview, prompt history, wrapping each of several carets, `lorem`, filters, custom abbreviations, CSS, part d (tag navigation). Deferred minors from review: an open snippet session can go stale after a wrap with no Tab stops; content that is only U+0001 reports "Not an Emmet abbreviation"; a text-only target (`div>{x}`) ignores block/per-line layout; pasting into the prompt does not clear the error label while Ctrl/Alt chords do; mixed tab/space indentation dedents by character count.

## Milestone 48: Emmet, part d (tag navigation) (2026-10-09)

Five commands in `html htm xhtml php phtml twig erb ejs njk hbs vue svelte jsx tsx` files (setting `emmet` on, one caret or selection; otherwise a toast): `Alt+Z` / `Alt+Shift+Z` balance a tag outward / inward, `Alt+]` / `Alt+[` select the next / previous tag name, attribute or attribute value, `Alt+S` updates the enclosing tag from an abbreviation. All are in the palette.

- Balance outward grows from a caret to the smallest inner or outer range that strictly contains the selection: the element's content, then the whole element, then the parent's content, and so on; a caret inside a tag's own text selects that element. Inward: a whole element gives its content, content gives the first child element, a bare caret gives the enclosing content; a non-empty selection that holds no element gives "Nothing inside" (it never grows).
- Items, in document order across every open tag: name, then each attribute (`href="x"`), then its value (`x`; empty values and valueless attributes have one stop). Past the last stop it wraps with the toast "Wrapped".
- Update tag: the prompt takes exactly one element (`div.box#a[x=1]`; children, siblings, groups, `*N` and `{text}` are refused with the "Not an Emmet abbreviation" prompt label, like wrap). A name renames the open and the close tag; without one (`.box`) the name is kept. Attributes with the same name (case-insensitive) are replaced in place, new ones are added after the last one, everything else, including line breaks inside the tag, is untouched. `.a.b` sets `class="a b"` (replacing it; `className` in jsx/tsx), `#x` sets `id`. Renaming a paired element to a void tag, or a void element to a paired one, is refused. One undo step (`Undid: update tag`); the caret ends after the new open tag. Read-only buffers refuse.
- Rulings: an unclosed non-void tag (`<p>` with no `</p>`) has no content range, only the tag itself; a caret at the end of an element belongs to it and a caret at its start belongs to the parent (`<div>|<p>` is in the div, `<br>|` is the br); `Alt+[` cannot be told from the start of a terminal escape sequence in legacy terminals, so it only works where the kitty keyboard protocol is on (the palette and rebinding always work); in JSX `<Link>` is not void and `<>...</>` fragments pair.
- Key choice: `Alt+K` (word swap, units, colours, LSP hover), `Alt+X` (eval plugin) and `Alt+G` (cite plugin) were already taken, so balance is `Alt+Z` / `Alt+Shift+Z` and update-tag `Alt+S`. A selected element is the update-tag target (not its parent).
- Not done: per-word class stops, several carets, matching-tag highlighting, remove-tag, split/join, go-to-pair, a live preview in the prompt. Known, minor: in JSX a `<` touching the previous word (`i<n`, `useState<string>`) is never a tag, so `foo<b>` written without a space in JSX text is missed; bracket attributes beat `.classes` whatever their order (`.a[class=c].d` gives `c`).

Code: `tagscan.rs` (scanner and all the logic, pure, char indices), `emmet::parse_tag_spec` / `is_void`, `App::tag_ctx`, `emmet_balance`, `emmet_select_item`, `emmet_update_prompt`, `emmet_update` in `app/extras.rs`, `Cmd::EmmetBalance` / `EmmetItem` / `EmmetUpdateTag`, `PromptKind::EmmetUpdate` / `EmmetUpdateBad`. Spec `docs/superpowers/specs/2026-10-09-emmet-tagnav-design.md`, plan `docs/superpowers/plans/2026-10-09-emmet-tagnav.md`.

Tested: 43 new tests (646 total, all passing): scanner, balance, stops and wrapping, enclosing, update-tag cases, `parse_tag_spec`, keymap; tmux with a throwaway `HOME`: balance out to the whole div and the "No enclosing tag" toast, balance in back down and "Nothing inside", `Alt+]` through every stop and its wrap, update-tag renaming and merging attributes with one-step undo, bad abbreviation keeping the prompt and its label resetting on Backspace, `br` onto a paired tag refused, `div` onto `<br>` refused, `hr.x` onto `<br>`, a `.css` file refusal, two carets.
