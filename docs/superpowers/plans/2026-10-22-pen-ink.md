# Pen Ink Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Write by hand with a pen: ink draws in place on the Endless canvas (and, optionally, in Markdown notes, pushing the text below down), then saves as an SVG shown in place.

**Architecture:** A pure `ink` module in `crates/app` holds strokes, grouping, shrink, SVG write/read and a stroke rasteriser (no UI, fully unit-tested). A `pen` module in `crates/gui` turns Wayland `zwp_tablet_v2` events into `PenEvent`s and routes them to the app as ink input, or as synthesised mouse events when ink is off. In Markdown the unsaved ink is a virtual block of rows under its anchor line (the existing embed `Blocks` mechanism), so the text below moves down by whole rows; nothing touches the note until save. Saved ink is a `![[handwriting/<id>.svg]]` line drawn by the inline-picture path from our own rasteriser.

**Tech Stack:** Rust 2021; `wayland-client` + `wayland-protocols` (feature `unstable`), linux-only direct dependencies of `crates/gui`, approved by the user 2026-10-22 (both already in `Cargo.lock` via winit). No SVG crate: SVG is written by hand and our own strokes are rasterised by us.

**Spec:** `docs/superpowers/specs/2026-10-22-pen-ink-design.md`. Executors read it first; it records which calls were the user's and which were mine.

## Global Constraints

- Linux/Wayland first (user runs Hyprland); no pen backend available means the pen is a mouse or touch exactly as today.
- Ink defaults: pen draws (`ink_pen = on`); Markdown drawing `ink_in_markdown = off` (user's decision); Endless always draws; `ink_pause = 1.5` s; `ink_extend_saved = off`; `ink_shrink_height = 1.0` text rows.
- Colour from the skin's text colour (`text.fg` role); no hard-coded RGB in drawing code. Button looks come from `ui.*` skin keys.
- Files: `handwriting/<id>.svg` under `<note folder>/`; note gets `![[handwriting/<id>.svg]]` on its own line; Endless ink is a box whose text is that line (one ordinary `box` line in the `.layout`).
- Pending ink is never silently dropped: any other input saves the group first.
- Touch is ignored while a pen is in range and for 300 ms after it leaves (my call, spec: palm rejection).
- No new crates beyond the two named above. Settings keys are plain `settings.conf` keys (legacy editor ignores them; compat tests must still pass).
- Budgets in `docs/perf.md` apply (keypress to pixels <= 8 ms p95; idle CPU 0%). Notes without ink and users without a pen take today's code path.
- `cargo test --workspace` and `cargo build --release` pass before the work is called done; the terminal build (`meridian-tui`) is unchanged.

## Review Focus

- Pen goes down on the last line of the note, or on the last visible row: the ink band still fits on screen, the page scrolls to keep it visible, and nothing panics.
- A stroke of one point (a dot) or two identical points: draws a dot, saves a valid SVG, and the shrink step does not divide by zero.
- Pen lifts, then the window closes or the user switches notes before the pause fires: the ink is saved, not lost.
- The saved SVG's file name already exists (two saves in the same millisecond): a different file is written, never an overwrite (except the explicit extend-saved case).
- The pen leaves the window mid-stroke or the tablet tool disappears: the stroke ends cleanly and the group is not stuck "drawing".
- Zoom or font size changes while ink is pending or after it is saved: ink scales with the text and stays aligned to its line.
